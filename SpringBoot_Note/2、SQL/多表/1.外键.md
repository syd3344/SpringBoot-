## 什么是外键

> - 外键约束是一种用来维护数据完整性和表间关系的  **==机制==**。
> - **它定义了某个表中的一个列或多个列，作为另一张表的外键，确保该列的值必须在被引用表的主键或唯一键中存在。**



## 外键的作用

> - **数据完整性**：
>   -  **==保证表与表之间的数据关系是一致的，防止孤立的数据出现==**。
> - **约束操作**：
>   - 外键约束可以限制某些操作的执行
>     - 比如删除或更新数据时，通过外键约束确保相关的关联数据不会被误删或更新。



## 物理外键

### 概述

> - **物理外键**是数据库中通过外键约束（`FOREIGN KEY`）直接定义的表间关系，数据库会自动对外键进行检查，确保数据的完整性和一致性
> - 物理外键会在数据库层面强制执行这些约束。

### 基本语法

> - 在创建表时，可以通过 `FOREIGN KEY` 关键字来定义外键  ( foreign key ) ( references )

```mysql
CREATE TABLE 子表 (
  列名 数据类型,
  ...
  FOREIGN KEY (子表列) REFERENCES 父表(父表列)
);
```

### 示例

```mysql
CREATE TABLE departments (
    dept_id INT PRIMARY KEY,      -- 部门ID
    dept_name VARCHAR(50)         -- 部门名称
);

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,       -- 员工ID
    emp_name VARCHAR(50),         -- 员工姓名
    dept_id INT,                  -- 部门ID
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id) -- 定义外键
);

```

### 场景实例

> - 我们有两个表：`departments` 和 `employees`，它们通过外键关联。
> - `employees` 表中的 `dept_id` 字段引用了 `departments` 表中的 `dept_id`，即员工属于某个部门。

#### 数据库表结构

```mysql
-- 部门表
CREATE TABLE departments (
    dept_id INT PRIMARY KEY AUTO_INCREMENT,
    dept_name VARCHAR(100) NOT NULL
);

-- 员工表
CREATE TABLE employees (
    emp_id INT PRIMARY KEY AUTO_INCREMENT,
    emp_name VARCHAR(100) NOT NULL,
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id) ON DELETE CASCADE
);
```

#### 测试数据

```mysql
-- 插入部门数据
INSERT INTO departments (dept_name) VALUES ('HR'), ('Finance'), ('IT');

-- 插入员工数据
INSERT INTO employees (emp_name, dept_id) VALUES ('Alice', 1), ('Bob', 2), ('Charlie', 3);
```

#### 查询场景

> - 假设我们需要查询每个部门中的员工信息，展示出所有部门和员工的对应关系。
> - 我们可以使用 **联接 (Join)** 来进行多表查询。

#### Sql语句

```mysql
SELECT d.dept_name, e.emp_name
FROM departments d
LEFT JOIN employees e ON d.dept_id = e.dept_id;
```

![1728421523650](1.外键.assets/1728421523650.png)

> - 这个查询结果展示了部门与其对应的员工信息。即使某些部门没有员工（例如在使用 `LEFT JOIN` 的情况下），这些部门也会出现在结果中。

### 优缺

> - **优点**：
>   - **数据完整性**：自动强制执行父表和子表之间的数据关系。
>   - **防止孤立数据**：防止在子表中出现没有在父表中存在的引用（例如防止分配给不存在的部门的员工）。
>   - **数据库级约束**：不依赖应用程序，数据层本身就可以控制关系的完整性。
> - **缺点**：
>   - **性能问题**：**==在高并发的系统中，外键约束可能会对性能产生影响==**，尤其是在插入、更新和删除时，数据库需要不断检查和维护这些关系。
>   - **复杂的表间操作**：当表间关系复杂时，删除或更新一条记录需要级联操作可能会变得非常麻烦，甚至**==会导致锁表或死锁问题==**。
>   - **迁移复杂**：由于数据库层次的严格性，**==涉及外键约束的数据库迁移可能更难实现==**，尤其是当数据量大或表结构复杂时。



## 逻辑外键

### 概述

> - **逻辑外键**不是通过数据库层面的外键约束来实现的，而是通过应用程序逻辑来维护表与表之间的关系。
> - 在数据库中，不会明确地定义 `FOREIGN KEY`，但是  **==在应用代码中会通过查询和数据校验来维护这些表之间的关系==**

### 优缺

> - #### **优点**：
>
>   - **更灵活的控制**：应用程序可以通过业务逻辑自定义数据的约束规则，提供更灵活的控制。
>   - **性能更好**：**==没有物理外键的开销==**，数据库只需要专注于存储和查询数据，不需要处理额外的约束检查。
>   - **简化数据库操作**：删除、更新等操作不需要考虑表之间的物理约束，操作更简洁。
>
> - #### **缺点**：
>
>   - **需要额外的应用程序逻辑**：数据完整性检查从数据库转移到了应用层，开发者需要手动确保在应用代码中处理这些约束。
>   - **数据一致性风险**：如果没有正确处理，可能会导致数据不一致的问题，比如插入了孤立数据（没有对应父记录的子记录）。
>   - **依赖于业务逻辑**：**==如果多个应用程序都使用同一个数据库，那么不同的应用程序可能有不同的逻辑，难以统一管理数据完整性。==**

### 场景实例

> - 假设我们有两个实体：**员工 (Employee)** 和 **部门 (Department)**
> - 我们希望确保员工的部门ID在部门表中存在。
> - 逻辑外键可以通过业务逻辑在数据插入或更新时进行验证。

#### 数据库表结构

```mysql
CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(100)
);

CREATE TABLE employees (
    emp_id INT PRIMARY KEY AUTO_INCREMENT,
    emp_name VARCHAR(100),
    dept_id INT
);
```

#### Mapper

#### Service

```java
@Service
public class EmployeeService {

    @Autowired
    private DepartmentMapper departmentMapper;

    @Autowired
    private EmployeeMapper employeeMapper;

    public void addEmployee(String empName, int deptId) {
        // 检查部门是否存在
        if (departmentMapper.countById(deptId) > 0) {
            // 插入员工
            employeeMapper.insertEmployee(empName, deptId);
        } else {
            throw new RuntimeException("部门不存在，无法插入员工");
        }
    }
}
```

#### Controller

```java

@RestController
@RequestMapping("/employees")
public class EmployeeController {

    @Autowired
    private EmployeeService employeeService;

    @PostMapping
    public String addEmployee(@RequestParam String empName, @RequestParam int deptId) {
        try {
            employeeService.addEmployee(empName, deptId);
            return "员工添加成功";
        } catch (Exception e) {
            return e.getMessage();
        }
    }
}
```
