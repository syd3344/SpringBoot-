## 概述

> - 用于确保一组操作要么全部成功，要么全部失败，即保证数据库的一致性、隔离性、持久性和原子性（ACID特性）



## 四大特性

> - **原子性（Atomicity）**：事务中的所有操作要么全部完成，要么全部不执行。原子性确保即使系统发生故障，也不会部分执行事务。
> - **一致性（Consistency）**：事务执行前后，数据库的完整性约束不会被破坏。即事务在开始和结束时，数据库都处于合法状态。
> - **隔离性（Isolation）**：多个事务并发执行时，它们的执行结果应该和按顺序执行一样。隔离性确保事务不会互相干扰。
> - **持久性（Durability）**：一旦事务提交，它的结果将永久保存在数据库中，即使发生系统故障，数据也不会丢失。



## 基本操作

> - 开始事务
>   - 
> - 提交事务
>   - commit
> - 回滚事务
>   - rollback

### 开启事务

> - 通常在使用事务时，需要明确开启事务（不同数据库处理方式略有不同）

```
START TRANSACTION;
```



### 提交事务

> - 会将事务的所有更改保存到数据库中

```mysql
COMMIT;
```



### 回滚事务

> - 事务中某一步失败，可以通过回滚撤销所有更改

```mysql
ROLLBACK;
```



### 示例

#### 场景

> - 假设我们有两个账户表 `accounts`，分别为 A 和 B 账户，A 转账给 B。
> - 为了保证在转账过程中不会发生数据不一致的情况（如转出成功但转入失败）

#### sql实现

```mysql
-- 开始事务
START TRANSACTION;

-- A账户扣除金额
UPDATE accounts SET balance = balance - 100 WHERE account_name = 'A';

-- B账户增加金额
UPDATE accounts SET balance = balance + 100 WHERE account_name = 'B';

-- 提交事务（若以上两步都成功）
COMMIT;

-- 如果某一步出错，使用回滚撤销操作
ROLLBACK;
```



> - 在这个过程中，如果某个步骤出现问题，例如 B 的账户更新失败，那么回滚操作将撤销 A 的账户扣款，确保两者要么都执行，要么都不执行



## java层的实现

### @Transactional

> - 通过注解来声明事务，该注解可以用在类或方法上
> - 为被它标注的类或方法提供事务支持
> - 它的最小单位时方法，如果想要更细粒度的控制需要使用编程式事务管理

```java
@Service
public class AccountService {

    @Autowired
    private AccountDao accountDao;

    // 将该方法放在事务中
    @Transactional
    public void transferMoney(String fromAccount, String toAccount, BigDecimal amount) {
        accountDao.debit(fromAccount, amount);  // 从 fromAccount 扣除金额
        accountDao.credit(toAccount, amount);   // 向 toAccount 添加金额
    }
}
```



> - `@Transactional` 注解确保 `transferMoney` 方法中的操作在事务范围内。
> - 如果操作中的任意一步失败（抛出异常），事务将回滚，所有的数据库修改都将被撤销。



### 回滚机制

> - 默认情况下，Spring 的事务管理会在 `RuntimeException` 或 `Error` 异常发生时回滚事务。
> - 如果你希望在某些检查性异常（如 `SQLException`）发生时也回滚事务，你可以使用 `rollbackFor` 属性指定需要回滚的异常类型。



### @Transactional 常用属性

> - **propagation**：事务的传播行为，定义事务的传播方式，常用值包括：
>   - `REQUIRED`（默认）：如果当前没有事务，则创建一个新的事务；如果已经存在事务，则加入当前事务。
>   - `REQUIRES_NEW`：每次都会启动一个新的事务，当前事务将被挂起。
>   - `NESTED`：嵌套事务。
> - **isolation**：事务的隔离级别，定义多个事务如何相互隔离，常用值有：
>   - `DEFAULT`：使用底层数据库的默认隔离级别。
>   - `READ_UNCOMMITTED`：允许读取未提交的更改，最低隔离级别。
>   - `READ_COMMITTED`：只允许读取已提交的数据，防止“脏读”。
>   - `REPEATABLE_READ`：防止“不可重复读”，保证同一事务中多次读取相同数据结果一致。
>   - `SERIALIZABLE`：最高隔离级别，完全串行化，防止“幻读”。
> - **timeout**：设置事务的超时时间（以秒为单位）。如果事务在指定时间内没有完成，则回滚事务。
> - **readOnly**：如果只执行查询操作（没有更新），可以将事务设置为只读，以优化性能。
> - **rollbackFor**：指定哪些异常类型会触发事务回滚。默认情况下，事务会在遇到 `RuntimeException` 或 `Error` 时回滚。
> - **noRollbackFor**：指定哪些异常类型不会触发事务回滚。
